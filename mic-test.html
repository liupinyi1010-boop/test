已知情況（查過的資料）

  

    
Chrome iOS（CriOS，例如 157）是用 Apple 的 WKWebView，不是 Android 那套 Google 語音服務。頁面上通常看得到 webkitSpeechRecognition，但真正辨識要靠 iOS 的 Speech 框架。

    
WebKit 錯誤 239816（2022，Google 工程師回報）：Safari 可以用 Web Speech API，其他內嵌 WKWebView 的 App 若 Info.plist 沒有 NSSpeechRecognitionUsageDescription，start() 會得到 service-not-allowed。這和麥克風「已允許」是兩件事；not-allowed 才是麥克風權限被擋。

    
Can I Use：Safari on iOS 14.5–26.6 對語音辨識是部分支援；沒有單獨的「Chrome iOS」列，因為 CriOS 跟 WebKit 走同一條路。Chrome 157 在桌面／Android 是部分支援，不能代表 iPhone Chrome 一定能用。

    
若 Chrome 已加上語音辨識說明字串，還要在系統設定打開「語音辨識」。請在這支 iPhone 檢查：

    
    
      
  1. 設定 → Chrome → 打開「麥克風」以及「語音辨識」（兩個都要開）
    2. 
      
  2. 設定 → 隱私權與安全性 → 語音辨識 → Chrome 要開啟
    3. 
      
  3. 設定 → 一般 → 鍵盤 → 聽寫：可先關掉再開一次
    4. 
    

    
來源：Google Chrome 說明（iPhone 麥克風）；Chrome 社群 2026-08 回覆亦寫需同時開啟 Microphone 與 Speech Recognition。

    
若以上都開了、這頁 A～G 仍然全部 service-not-allowed，而 Safari 同一個頁面可以辨識，就比較像是目前這版 Chrome App 仍未開放網頁語音辨識給 WKWebView，網頁端改 start 順序或語言也修不了。可用的後備：把游標放進輸入框，用鍵盤的麥克風聽寫（不走 Web Speech API），或用 Safari 開啟。
